NYC 311 SLA Compliance Analysis — Data Pull & Join Scaffold

Window: Jan 1, 2022 through Dec 31, 2025

Datasets:

- 311 Service Requests from 2020 to Present (erm2-nwe9)

- 311 Service Level Agreements (cs9t-e3x8)

What this script does:

1. Pulls the full SLA lookup table (small — ~1,500 rows).

2. Pulls SRs (sample mode for testing, full mode for production).

3. Parses the SLA “sla_days” string column into numeric hours + days.

4. Left-joins SLA targets onto SRs at the most granular key available.

5. Computes actual resolution time and SLA compliance flags.

Before you run:

- Get a free Socrata app token: https://data.cityofnewyork.us/profile/app_tokens

- Set as an env var SOCRATA_APP_TOKEN, or paste into the line below.

—- Timeout / retry tuning ————————————————-

Each Socrata page request will be given up to this many seconds before httr

gives up. Generous ceiling — pages normally come back in < 30s but can stall

during peak hours. You’d rather wait than crash mid-pull.

HTTP_TIMEOUT_SEC <- 600 # 10 minutes per page request MAX_RETRIES <- 5 # retries per chunk on transient failures (503, timeout) RETRY_BACKOFF_SEC <- 30 # initial backoff, doubles each retry

Chunk the full-year pull one month at a time so a failure at month 23 doesn’t

cost you months 1-22. Set FALSE if you want a single monolithic request.

CHUNK_BY_MONTH <- TRUE CACHE_DIR <- “socrata_cache” dir.create(CACHE_DIR, showWarnings = FALSE)

Anchor compliance calculations to a fixed date so re-running is reproducible.

Tickets still open as of this date that have already exceeded their SLA

window are treated as failures; tickets still open but within their SLA

window are treated as not-yet-evaluable. Without this anchor, results would

shift slightly every time the script runs.

ANALYSIS_AS_OF <- as.POSIXct(“2026-01-01 00:00:00”, tz = “UTC”)

Track total pipeline runtime for methodology reporting.

Helper: run an expression with a generous HTTP timeout and retries.

safe_socrata <- function(url, token, label = url) { attempt <- 0 repeat { attempt <- attempt + 1 result <- tryCatch( httr::with_config( config = httr::timeout(HTTP_TIMEOUT_SEC), read.socrata(url, app_token = token) ), error = function(e) e ) if (!inherits(result, “error”)) return(result) if (attempt >= MAX_RETRIES) { stop(“Failed after”, MAX_RETRIES, ” attempts on “, label,”error: “, conditionMessage(result)) } wait <- RETRY_BACKOFF_SEC * (2 ^ (attempt - 1)) message(” Attempt “, attempt,” failed (“, conditionMessage(result),”). Retrying in “, wait,”s…“) Sys.sleep(wait) } }

NYC 311 SLA Compliance — Chunked Join (Memory-Safe)

Reads each cached monthly SR file from socrata_cache/, prepares it, joins

it against the SLA lookup, computes compliance flags, and writes the

per-month result to processed_cache/. At the end, concatenates the small

per-month outputs into the final sr_with_sla.rds.

Why chunked: the full-data version of the prep + join holds multiple copies

of 13.5M rows in memory simultaneously and crashes on a 16 GB Mac. Processing

month-by-month keeps peak memory under 5 GB.

Run after the data has been cached by nyc311_sla_pull.R.
